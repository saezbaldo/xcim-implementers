# Contributing to XCIM Implementer Materials

Contributions should improve implementability without turning an open question
into an accidental normative requirement. Before opening a change:

1. Identify the draft version and the affected role (sending, receiving or infrastructure).
2. Separate protocol behavior from product-specific behavior.
3. Include a sanitized example or a reproducible test whenever possible.
4. Do not include recipient addresses, OAuth secrets, access tokens or predictable email hashes.
5. Mark unresolved behavior as an issue or ADR instead of silently choosing an alias.

Normative changes require an ADR or an explicit specification update. Security
reports use the security contact published by XCIM, not a public issue.
